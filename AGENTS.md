# Game Development Instructions

## Project
- This project is a small game.
- Prefer simple, maintainable solutions.
- Reuse existing systems and conventions.
- Avoid unnecessary dependencies.

## Before Coding
- Inspect only files relevant to the task.
- Reuse existing functions where possible.
- For complex changes, create a short plan first.
- Ask questions only when missing information blocks implementation.

## During Coding
- Make the smallest change that solves the task.
- Do not rewrite unrelated code.
- Avoid unnecessary abstraction or overengineering.
- Preserve existing gameplay behavior unless requested.
- Do not create duplicate systems.

## After Coding
- Run relevant tests or checks.
- Fix errors caused by your changes.
- Do not repeatedly run the same failing command without changing the approach.
- Summarize changes briefly.

## Token Efficiency
- Avoid reading the entire repository.
- Prefer targeted file searches.
- Keep explanations concise.
- Do not launch subagents unless useful.
- Avoid unnecessary documentation generation.
- Never sacrifice correctness to save tokens.
